### 为什么引擎必须零 DOM 依赖

因为你需要**用脚本批量跑 10000 局**来验证平衡。这是唯一能客观回答"这个游戏是不是只有一个解"的方法。如果引擎和 React 缠在一起，这件事就做不了，平衡只能靠手感——而手感必崩。

## 3. 核心数据结构

```ts
// ---------- 基础 ----------
type DateStr = string;        // 'YYYY-MM-DD'
type Money = number;          // 美元，浮点。展示层负责格式化
type Ratio = number;          // 比率，0.05 = 5%

// ---------- 配置 ----------
interface GameConfig {
  seed: number;                        // 决定一切随机
  difficulty: 0 | 1 | 2 | 3;
  identity: 'retail' | 'hedge_fund' | 'bank' | 'insurer';
  initialCapital: Money;               // 受难度约束区间
  ironman: boolean;                    // 默认 true
  timeline: 'historical' | 'parallel'; // 平行时间线 = 关键事件可被改写
  startDate: DateStr;                  // 默认 '2007-01-02'
  endDate: DateStr;                    // 默认 '2009-12-31'
}

// ---------- 标的 ----------
type AssetClass = 'equity' | 'index' | 'future' | 'option' | 'cds' | 'otc';

interface Instrument {
  id: string;                  // 'LEH', 'SPX', 'SPX-2008-12-P-800'
  name: string;
  assetClass: AssetClass;
  currency: 'USD';
  sector?: string;             // 'financials' | 'housing' | 'energy' ...
  // 契约
  multiplier: number;          // 合约乘数
  tickSize: number;
  // 期权/衍生品专属
  underlying?: string;
  expiry?: DateStr;
  strike?: number;
  optionType?: 'call' | 'put';
  // 可交易性
  tradable: boolean;
  shortable: boolean;          // 动态可变（做空禁令！）
  marginRequirement: Ratio;    // 初始保证金率，动态可变
}

// 每个标的每日的行情
interface DailyBar {
  date: DateStr;
  open: number; high: number; low: number; close: number;
  volume: number;
  // 派生指标（随难度解锁可见性）
  adv20?: number;              // 20日平均成交额，用于市场容量
  realizedVol?: number;
  creditSpread?: number;       // 信用利差（bp），CDS 代理
  impliedVolATM?: number;      // 平值隐含波动率
}

// ---------- 账户 ----------
interface Position {
  instrumentId: string;
  quantity: number;            // 正=多，负=空
  avgPrice: number;
  openedAt: DateStr;
  borrowFeeRate?: Ratio;       // 做空的借券费（年化），危机中飙升
  collateralPosted?: Money;    // 卖保护/场外合约的抵押品
}

interface Account {
  cash: Money;
  positions: Map<string, Position>;
  // 融资能力（P2+，这是本作的一等公民）
  repoCapacity: Money;         // 还能融多少钱
  repoHaircut: Ratio;          // 回购折扣率，危机中从 5% 飙到 45%
  // 风险
  grossExposure: Money;
  netExposure: Money;
  equity: Money;               // = cash + 持仓市值
  maintenanceMargin: Money;
  marginCall: boolean;
  // 统计
  peakEquity: Money;
  maxDrawdown: Ratio;
}

// ---------- 订单 ----------
interface Order {
  instrumentId: string;
  side: 'buy' | 'sell';
  quantity: number;
  type: 'market' | 'limit';
  limitPrice?: number;
  submittedAt: DateStr;        // t 日
}

interface Fill {
  order: Order;
  filledAt: DateStr;           // t+1 日
  price: number;               // 含滑点
  quantity: number;            // 可能部分成交
  impact: number;              // 本次成交造成的价格冲击
  commission: Money;
  reason?: 'ok' | 'insufficient_liquidity' | 'not_shortable' | 'margin_rejected';
}

// ---------- 事件与新闻 ----------
interface EventCard {
  id: string;
  phase: 0 | 1 | 2 | 3 | 4 | 5;    // 0=前奏 1=裂缝 2=贝尔斯登 3=两房与雷曼 4=全面冻结 5=见底反弹
  date: DateStr;                   // 历史实际日期（用于 historical 模式与校准）
  title: string;
  headline: string;                // 新闻标题（大字）
  narrative: string;               // 新闻正文
  window: [DateStr, DateStr];      // 触发窗口
  tier: EventTier;                 // 分层，见下

  // ---- 前置条件 ----
  requires: string[];              // 硬前置：事件 id 或状态谓词，全部满足
  requireAnyOf: string[][];        // 软前置：每组满足其一即可
  exclusiveWith?: string[];        // 互斥事件（如雷曼破产 vs 雷曼获救）

  // ---- 触发方式 ----
  trigger:
    | { type: 'scheduled'; probabilityPerDay: number; modeOnly?: 'parallel' }
    | { type: 'competing_risk'; institution: string; baseHazard: number;
        canonicalFirstDomino?: boolean; jitterDays?: number }
    | { type: 'state'; predicate: string; probabilityPerDay?: number };

  // ---- 效果 ----
  impact: ImpactVector;
  affectsFragility?: Record<string, number>;  // 对其他机构脆弱度的影响
  imposesRule?: ActiveRule;        // 注入监管规则（如做空禁令）

  // ---- 元数据 ----
  reversible: boolean;             // 是否可被玩家/NPC 行为阻止
  isSystemicEvent: boolean;        // 95% 以上运行中必触发
  isTrap?: boolean; trapNote?: string;
  isBottom?: boolean; isReversal?: boolean; isScorecard?: boolean;
  structural?: boolean;            // 结构性事件，不可随机
  newsVisibility: 0 | 1 | 2 | 3;   // 从哪个难度开始可见
  unlocks?: string[];              // 触发后解锁的事件（文档用途，非引擎必需）
  sources?: string[];              // 史实出处
}

type EventTier =
  | 'macro' | 'policy' | 'funding'                 // 宏观层
  | 'investment_bank' | 'commercial_bank'          // 机构层
  | 'insurer' | 'gse' | 'overseas';                // 特殊层

/** 状态谓词语法（用于 requires / requireAnyOf），见 docs/06 §8 */
type StatePredicate =
  | `credit_spread_above_${number}`
  | `player_short_concentration_${string}_above_${number}pct`
  | `vix_above_${number}`
  | `ted_spread_above_${number}`
  | `liquidity_below_${number}`
  | `srs_above_${number}`;

interface ImpactVector {
  targets?: string[];              // 受影响标的，缺省=全市场
  equityReturn?: number;           // 对相关股票的即期收益冲击
  indexReturn?: number;            // 对大盘的即期收益冲击
  volMultiplier?: number;          // VIX 乘数，如 1.35
  creditSpreadDelta?: number;      // 信用利差变化（bp）
  liquidityMultiplier?: number;    // 市场容量乘数，如 0.3
  decayDays: number;               // 冲击半衰期

  // ---- 融资维度（tier='funding' 的事件优先用这些，见 docs/07）----
  repoHaircutDelta?: number;       // 回购折扣率阶跃（如 +0.30）
  rolloverRateDelta?: number;      // 展期率变化（可为负 = 挤兑）
  borrowFeeMultiplier?: number;    // 借券费倍数（如 8.0 = 涨 8 倍）
  shortableRestriction?: boolean;  // 是否限制做空（无券可借）
  marginRequirementMultiplier?: number; // 保证金要求倍数
}

interface NewsItem {
  id: string;
  date: DateStr;
  headline: string;
  body: string;
  source: 'historical' | 'generated';
  credibility: number;             // 0–1，程序化传闻的可信度
  isTrue: boolean;                 // 内部字段，玩家不可见
  eventId?: string;
}

// ---------- 对手 ----------
interface NPCAgent {
  id: string;
  type: 'retail' | 'conservative_fund' | 'hedge_fund' | 'bank' | 'market_maker';
  equity: Money;
  leverage: Ratio;
  positions: Map<string, Position>;
  // 性格参数（决定行为异质性）
  params: {
    riskAppetite: number;
    trendSensitivity: number;   // 追涨杀跌强度
    redemptionPressure: number; // 被迫卖出压力
    informationLead: number;    // 提前知情天数（投行为 2–3 天）
  };
}

// ---------- 监管 ----------
interface RegulatorState {
  srs: number;                 // 系统性风险分 0–1+
  attention: 0 | 1 | 2 | 3 | 4 | 5;  // 监管阶梯 L0–L5
  activeRules: ActiveRule[];   // 生效中的规则（做空禁令等）
  playerFootprint: {
    shortConcentration: Ratio; // 你的空头占该股流通股比例
    priceImpactShare: Ratio;   // 你的交易贡献了多少市场跌幅
  };
}

interface ActiveRule {
  id: string;
  kind: 'short_ban' | 'margin_hike' | 'disclosure' | 'circuit_breaker' | 'bailout';
  scope: string[];             // 适用标的
  effectiveFrom: DateStr;
  effectiveTo: DateStr;
}

// ---------- 全局状态 ----------
interface GameState {
  config: GameConfig;
  date: DateStr;
  turnIndex: number;
  instruments: Map<string, Instrument>;
  bars: Map<string, DailyBar[]>;      // 历史（含玩家看不到的未来，UI 层负责裁剪）
  player: Account;
  agents: NPCAgent[];
  regulator: RegulatorState;
  activeEvents: string[];
  firedEvents: string[];
  news: NewsItem[];
  log: PlayerAction[];                // 操作日志 → 存档核心
  score: ScoreSnapshot[];
}
```

### 3.1 关键设计：UI 裁剪未来

`GameState.bars` 里**包含完整历史路径**（含未来），但 UI 层只被允许读取 `date` 及以前的切片。

**这是一个刻意的安全设计**：引擎不需要知道"玩家能看到什么"，它只需要保证成交发生在 t+1。UI 层通过一个 `visibleBars(state, instrumentId)` 函数统一裁剪。

- 好处：引擎简单、可批量跑；未来路径已生成，无性能问题。
- 风险：任何直接读 `state.bars` 的 UI 组件都可能泄露未来。
- 缓解：把 `bars` 改为私有字段，只暴露 `visibleBars()`。**不要为了方便而破例。**

## 4. 回合结算时序（伪代码）

```ts
function advanceTurn(state: GameState, pendingOrders: Order[]): TurnResult {
  const t = state.date;
  const t1 = nextTradingDay(t);

  // 1) 事件注入（在开盘前，玩家看不到）
  const firedToday = scenario.tick(state, t1);

  // 2) NPC 决策（同样看不到内容，但玩家能观察到结果）
  const npcOrders = agents.map(a => a.decide(state, t1));

  // 3) 市场生成 t+1 价格
  //    基础路径 → 跳扩散噪声 → 事件冲击 → NPC 净流量 → 玩家订单冲击
  const bars = market.generate(state, t1, firedToday, npcOrders, pendingOrders);

  // 4) 成交（以 t+1 开盘价 + 滑点）
  const fills = pendingOrders.map(o => market.execute(state, o, bars));

  // 5) 盯市结算
  portfolio.markToMarket(state, bars);

  // 6) 保证金检查 → 追保 → 强平
  portfolio.checkMargin(state);

  // 7) 监管评估（玩家足迹 → SRS → 阶梯）
  regulator.evaluate(state);

  // 8) 新闻发布（供玩家在 t+1 收盘后看到）
  news.publish(state, firedToday);

  // 9) 推进时钟
  state.date = t1;
  state.turnIndex++;

  return { fills, newBars: bars, news: news.since(t1) };
}
```

### 4.1 成交规则（防未来函数的全部规则）

| 规则 | 内容 |
|---|---|
| 定价基准 | 玩家订单以 **t+1 开盘价**成交，绝不用 t 日收盘价或 t+1 最高/最低价 |
| 滑点 | `成交价 = 开盘价 × (1 ± impact)`，方向永远对玩家不利 |
| 部分成交 | 超过 `市场容量` 的部分不成交（`reason: 'insufficient_liquidity'`） |
| 做空限制 | `instrument.shortable === false` → 拒单（做空禁令生效时） |
| 保证金拒单 | 建仓后会导致保证金不足 → 直接拒单，而不是先成交再强平 |
| 停牌 | 极端事件可令标的停牌，订单顺延或作废 |
| 无撤销 | 订单提交后不可撤销（t 日提交、t+1 成交，中间没有机会） |

> **"订单提交后不可撤销"是一条重要的设计选择。** 它把"想清楚了再下单"变成压力来源。真实市场里盘后下单也确实是这样。

## 5. 存档设计

**存档 = { 种子, 配置, 操作日志 }**，三个字段即可完整复现一整局。

```ts
interface SaveFile {
  version: 1;
  config: GameConfig;
  actions: PlayerAction[];   // 按回合排列的操作序列
  // 以下为冗余缓存，用于快速加载与校验，可随时丢弃重建
  cache?: { finalEquity: Money; finalDate: DateStr; checksum: string };
}
```

**收益**
- 存档极小（几十 KB）
- **种子对战**：分享 `seed` 字符串 + 配置，别人在完全相同的市场里挑战你的成绩。纯前端即可实现，零后端。
- **确定性回归测试**：`seed=42` + 固定操作序列 → 断言期末净值。任何引擎改动只要破坏确定性，测试立刻变红。
- **反作弊的天然基础**：排行榜只需提交 `{seed, actions}`，服务端重放即可验证，**不需要信任客户端**。

## 6. RNG 设计

**绝对不要用 `Math.random()`。** 必须用显式种子的 PRNG，并且**多流分离**：

```ts
class Rng {
  constructor(seed: number, stream: string) { /* hash(seed + stream) */ }
  next(): number;              // [0,1)
  normal(): number;            // 标准正态（Box-Muller）
  jump(lambda: number): boolean; // 泊松跳
}

const streams = {
  market:   new Rng(seed, 'market'),    // 价格噪声
  scenario: new Rng(seed, 'scenario'),  // 事件触发
  agents:   new Rng(seed, 'agents'),    // NPC 决策
  news:     new Rng(seed, 'news'),      // 传闻生成
};
```

**为什么要分四个流**：如果共用一个流，玩家在 t 日多下了一单（消耗一个随机数）就会改变后续所有事件的触发时间。分流域之后，玩家的行为**不会**扰动市场随机性，只有冲击成本会。这让种子对战公平、让调试可复现。

用 xorshift128 或 PCG32 即可，几十行代码，不要引库。

## 7. 事件卡系统

### 7.1 因果骨架必须锁死

```
房价下跌 → 次贷违约上升 → 结构化产品亏损 → 回购融资枯竭
   → 贝尔斯登倒下 → 两房被接管 → 雷曼倒下 → 货币基金跌破面值
   → AIG 被救助 → 全面信贷冻结 → 做空禁令 → TARP → 2009-03 见底反弹
```

用 `requires: string[]` 构成 DAG。**顺序固定，日期浮动。**

玩家应该能"从先行指标预感到危机"，而不是靠背历史日期。这才是教育价值所在。

### 7.2 三层扰动

| 层 | 机制 | 参数 |
|---|---|---|
| ① 时间抖动 | 事件在 `window` 内按 `probabilityPerDay` + 前置条件触发 | 窗口宽度随难度增加 |
| ② 幅度抖动 | `impact × (1 + ε)`，ε ~ N(0, σ²) | σ ≈ 0.3 |
| ③ 路径噪声 | 基础路径叠加跳跃扩散 | 日波动 + 泊松跳 |

**关键约束：新闻强度与价格冲击必须绑定。**

`impact` 是主项，`ε` 只是小扰动。如果让价格冲击独立随机，会出现"雷曼破产新闻 + 股价只跌 0.5%"的割裂感，玩家立刻会感到"随机数在糊弄我"，信任崩塌。

**随机的是"何时"和"多深"，不是"是否"和"方向"。**

### 7.3 平行时间线

当 `config.timeline === 'parallel'` 时，`reversible: true` 的事件有概率不触发或被提前救助（如"贝尔斯登被成功救助"）。这会**彻底改变最优策略**——做空的人反而亏钱。这是重玩性的核心来源，成本极低。

### 7.4 玩家改写历史（P3）

如果玩家把某机构的空头做到极致，且该机构 `EventCard.reversible`，则该机构真的可能被玩家做垮。此时事件卡**由玩家触发**，历史被改写。

这自然地引出：**高难度玩家会亲手制造危机，然后被监管盯上。** 见 [03 文档 §8](03-金融模型与数值.md)。

## 8. 未来函数防护清单

这是本作的头号死因。逐条检查：

- [ ] 成交价只用 t+1 开盘价，永不使用 t 日或 t+1 的其他价格
- [ ] UI 读行情必须经过 `visibleBars()`，不允许直接访问 `bars`
- [ ] 新闻发布日期 ≤ 当前回合
- [ ] 指标（如 20 日 ADV、实现波动率）只用历史窗口计算
- [ ] 财报数据在**发布日期**才可见，不是报告期
- [ ] 评级下调、CDS 利差更新都存在**发布滞后**（真实世界 1–3 天）
- [ ] 事件卡的 `requires` 只能引用已触发事件，不能引用未来
- [ ] 回测/蒙特卡洛模式与手动模式走**同一条代码路径**（避免"测的时候对、玩的时候错"）
- [ ] 单元测试里有一条专门断言："t 日可见信息集合 ⊄ 决策所需信息集合"

### 9.1 三层测试

| 层 | 内容 | 工具 |

| 单元测试 | 保证金计算、强平触发、BS 定价、滑点公式、DAG 拓扑排序 | Vitest |
| 确定性回归 | `seed=42` + 30 步固定操作 → 快照断言 | Vitest snapshot |
| 批量对局 | 10000 局 × 策略机器人 × 各难度，检验平衡 | `tools/sim` |

### 9.2 策略机器人池（平衡验证的核心工具）

让以下机器人各跑 1000 局，比较净值分布：

| 机器人 | 策略 | 期望结果 |
|---|---|---|
| `DoNothing` | 全程空仓 | 应能拿到中上评分，不应垫底 |
| `BuyAndHold` | 期初买入持有 | 应大幅亏损但不能爆仓 |
| `AllInShort` | 全仓做空并持有 | **不应稳赢**（否则平衡失败） |
| `ShortThenFlip` | 做空到 2009-03 反手做多 | 应是高分策略（奖励正确判断） |
| `TrendFollow` | 简单趋势跟踪 | 中等 |
| `RandomValid` | 随机合法操作 | 应接近垫底 |
| `AlwaysHedged` | 恒定对冲 | 应低波动、低收益 |

**判定标准：如果 `AllInShort` 的净值分布显著优于 `ShortThenFlip`，且几乎不爆仓，说明难度设计失败，必须回头调参。** 这是唯一客观的平衡检验方法。

### 9.3 数值稳定性注意

- 全部金额用浮点 `number`（$ 级别精度足够），**不要用整数分**——合约乘数和期权定价会让换算变成负担。
- 保证金、强平判定加 `1e-6` 容差，避免浮点误差导致"差一分钱被强平"。
- 期权 `T → 0` 时使用内在价值，避免 `d1/d2` 除以零。
- `sqrt` 的负数保护：冲击律里 `Q/V` 可能溢出，需要 clamp。
