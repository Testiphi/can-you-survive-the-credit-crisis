## 2. 设计意图：四条"叙事弧"

事件卡不是平铺的清单，它们构成四条同时运行的弧线。

### 弧线一 · 因果链（不可随机）

```
房价下跌 → 次贷违约 → 结构化产品亏损 → 回购融资枯竭
  → 银行间冻结 → 首个机构倒下 → 传染 → 系统性崩塌 → 政策救助 → 见底 → 反转
```

这条弧线的**方向与顺序固定**，因为它是物理因果。任何打乱它的尝试都会让游戏变得不可信。

### 弧线二 · 机构死亡链（可随机 ★）

```
贝尔斯登 / 雷曼 / 美林 / 摩根士丹利 / 高盛
        ↑ 谁先倒由竞争风险模型决定
```

这条弧线**顺序可以变化**，但变化来自机构脆弱度状态，而不是随机洗牌。详见 [05 文档](05-事件系统与危机排序机制.md)。

### 弧线三 · 政策响应链（半固定）

```
降息 → 紧急降息 → 流动性工具 → 担保 → 注资 → 直接购买资产 → 零利率与 QE
```

政策工具是**逐级加码**的，但在每一步"加码多少、什么时候加"上有抖动空间。

### 弧线四 · 融资链（★ 本作独有）

见 [07-回购市场与融资机制](07-回购市场与融资机制.md)。这条弧线**不冲击股价，只冲击融资能力**：

```
haircut 第一次跳升（2007-08）→ 期限缩到隔夜（2007-09）→ 出借方撤退（2007-11）
  → 贝尔斯登回购挤兑（2008-03）→ 三方回购集中度暴露（2008-03）
  → haircut 第二次跳升（2008-06）→ 雷曼回购挤兑（2008-09）
  → AIG 证券借贷挤兑（2008-09）→ haircut 跳到 45–100%（2008-09）
  → 三方回购冻结（2008-09）→ 货币基金撤出（2008-09）
  → 借券枯竭、做空成本飙升（2008-09）→ CPFF（2008-10）
  → 火售螺旋（2008-10）→ 连国债抵押品都被打折（2008-10）
  → 回购市场正常化（2009-06）
```

**这条弧线是 D2/D3 的核心内容，也是难度梯度最纯粹的体现：**

| 同一件事 | D0 玩家看到 | D2 玩家看到 |
|---|---|---|
| 2007-10-09 标普创新高 | "牛市还在" | "信用市场已经冻结两个月" |
| 2007-11-15 出借方撤退 | 没有这条新闻 | **"我的融资可能要断了"** |
| 2008-09-16 haircut 到 45% | 只看到股价跌 | **"抵押品不能再用来借钱了"** |

**同一场危机，两种完全不同的游戏。** 这就是本作难度设计的目标形态。

## 4. 五张最关键的事件卡

### 4.1 `bear_stearns_collapse` — 第一个多米诺

**为什么它是必做的**：它是整场危机的分水岭。在它之前，主流观点认为"次贷是局部问题"；在它之后，所有人都知道投行会死。

**设计要点**
- 冲击向量极端：`equityReturn: -0.90`（从 170 美元到 2 美元），但 `indexReturn` 只有 -0.011。**个股毁灭 ≠ 大盘崩盘**——这个区分很重要。
- `affectsFragility` 对 LEH +0.18、MER +0.14。它是传染的源头。
- `trigger.type = competing_risk`，`canonicalFirstDomino: true`。在历史参数下它约 62% 概率是第一个，但**不是强制的**。

**玩家体验**：如果玩家在 3 月 13 日做空了贝尔斯登，他会在三天内赚到 90%。这会让他产生"我很厉害"的错觉——然后在雷曼身上把利润还回去。

### 4.2 `lehman_collapse` — 整场危机的中心

**设计要点**
- `requireAnyOf` 有四条路径：历史路径（贝尔斯登已倒）、美林先倒的变体、信用事件先到、**玩家做空引发**。这让它成为整个数据集里最灵活的节点。
- 冲击是全表最强：`volMultiplier: 2.10`、`liquidityMultiplier: 0.15`、`creditSpreadDelta: 320`。
- `decayDays: 45` —— 它不是一天的事件，是一个半月的状态。

**平行时间线变体**：`lehman_rescue_variant`（`exclusiveWith: lehman_collapse`）在 parallel 模式下有 18%/天的触发概率。**它存在的唯一目的是让"无脑做空"不再安全。** 如果雷曼被救了，做空者会在一天内亏掉一年的利润。

### 4.3 `aig_bailout` — 反直觉的一课

**设计要点**
- AIG 的杠杆率只有 11 倍（见 `institutions.json`），按传统标准它"不危险"。但它卖出 4400 亿美元名义额的 CDS 保护。
- 它的脆弱度来自 `counterpartyExposure: 0.88` —— 全表最高。
- 叙述里刻意写明了核心教训：**"不是你判断错了，是你在正确的时候被融资断了。"**

这是全作最好的一个教学点：**传统杠杆率会骗人，尾部风险不会。**

### 4.4 `sec_short_ban` — 对做空策略的终极反制

**设计要点**
- `imposesRule: { kind: "short_ban", scope: ["financials"], durationDays: 19 }`
- `equityReturn: +0.12`，`indexReturn: +0.040` —— **这是一个对多头有利的事件。**
- 规则到期后由引擎自动生成新闻（见 `events-2009.json` 的 `autoGeneratedNews`），不需要单独的事件卡。

**为什么它重要**：它让"做空"从"一个策略"变成"一个在特定时间窗口内被法律禁止的策略"。玩家必须学会：**监管风险是持仓风险的一部分。**

同时它是**双向**的——如果你是多头，这一天是你的救星。监管从来不是只朝一个方向。

### 4.5 `citi_profit_announcement` — 做空者的清算日

**设计要点**
- 触发于 `sp500_bottom_666` 之后，`equityReturn: +0.38`、`indexReturn: +0.064`、`decayDays: 60`。
- 它不是"危机结束"，它只是花旗 CEO 的一封内部信被泄露。**反转的起点可以是一件很小的事。**
- `sp500_bottom_666` 带 `jitterDays: 20` —— **底部时点本身是随机的**，这直接杀死了"精准抄底"策略，只留下"分批建仓"。

**玩家体验**：从这里开始，所有坚持做空的玩家进入亏损。这一年剩下的时间都在惩罚他们。

## 5. 陷阱设计（4 个）

| 陷阱 | 日期 | 表面信号 | 真实情况 |
|---|---|---|---|
| `sp500_all_time_high` | 2007-10-09 | 股指创历史新高 | 信用市场已经冻结两个月 |
| `false_calm` | 2007-11-01 | 官方称"基本受控" | 回购折扣率正在系统性上升 |
| `false_calm_summer2008` | 2008-05-15 | VIX 回到 20 以下，投行 CEO 说危机结束 | 距离雷曼倒下只剩四个月 |
| `sp500_low_nov2008` | 2008-11-20 | 跌了 52%，"还要继续跌" | 距离真正的底只差 10%，但距年末反弹后的水平差了 48% |

**设计原则**：陷阱不是让你亏钱，是让你**在错误的信息下自信地做决定**。每个陷阱事件都有 `trapNote` 字段说明设计意图。

**关键**：陷阱必须**可被识破**——通过那些不在 D0 玩家视野里的指标（回购折扣率、ABCP 发行量、TED 利差）。这就形成了难度的自然梯度：D0 玩家会掉进陷阱，D2 玩家能看到陷阱底下的东西。

## 6. 随机性作用在哪、不作用在哪

| 维度 | 固定 | 随机 |
|---|---|---|
| 因果方向 | ✅ 房价→违约→亏损→融资断裂 | |
| 事件顺序（宏观链） | ✅ | |
| 机构死亡顺序 | | ✅ 竞争风险模型 |
| 事件日期 | | ✅ `window` 内浮动（jittered ±10 交易日） |
| 冲击幅度 | | ✅ `impact × (1+ε)`，ε ~ N(0, 0.3²) |
| 底部时点 | | ✅ `jitterDays: 20` |
| 路径噪声 | | ✅ 跳跃扩散 |
| 关键事件是否发生 | | ✅ 仅 `reversible: true` 的卡，且仅 parallel 模式 |
| 新闻与冲击的绑定 | ✅ 强度必须一致 | |

**一句话原则：随机的是"何时"和"多深"，不是"是否"和"方向"。**

## 7. 传闻系统（`rumors.json`）

**38 类**程序化传闻，解决"信息即难度"的问题。

| 类别 | 条数 | 代表条目 |
|---|---|---|
| **融资/回购** | **6** | `rumor_repo_haircut_jump`（折扣率将跳升）、`rumor_repo_maturity_shortening`（期限缩短）、`rumor_credit_line_pulled`、`rumor_custody_freeze`、`rumor_derivative_netting_failure`、`rumor_margin_hike` |
| 机构困境 | 5 | `rumor_liquidity_strain`、`rumor_counterparty_pullback`、`rumor_bank_run`、`rumor_broker_dealer_failure`、`rumor_ceo_resignation` |
| 信用/评级 | 5 | `rumor_rating_downgrade`、`rumor_insurer_downgrade_cascade`、`rumor_gse_capital_shortfall`、`rumor_municipal_contagion`、`rumor_sovereign_downgrade` |
| 政策 | 5 | `rumor_bailout_coming`、`rumor_no_bailout`、`rumor_fed_emergency_meeting`、`rumor_tarp_expansion`、`rumor_bank_holiday` |
| 监管 | 5 | `rumor_short_ban_consideration`、`rumor_prosecution`、`rumor_short_interest_probe`、`rumor_sec_watching_player`、`rumor_disclosure_breach` |
| 市场资金流 | 8 | `rumor_fund_liquidation`、`rumor_hedge_fund_gate`、`rumor_redemption_wave`、`rumor_market_maker_pullback`、`rumor_hedge_fund_wins`、`rumor_sovereign_wealth_injection`、`rumor_buffett_capital`、`rumor_merger_talks` |
| 盈利/减记 | 3 | `rumor_writedown`、`rumor_cdo_valuation_dispute`、`rumor_auditor_qualification` |
| 宏观 | 1 | `rumor_recovery_signal` |

**核心机制**
- 每条传闻有 `trueProbability`，可被市场状态放大（如机构脆弱度 > 0.75 时，关于它的困境传闻真实概率 ×2.2）。
- 玩家观察到的是**带噪声的可信度**：`observedCredibility = clamp(true + N(0, 0.18), 0.05, 0.95)`。
- 真消息比例与噪声随难度变化：

| 难度 | 真消息比例 | 可信度噪声 σ | 可见类别 |
|---|---|---|---|
| D0 | 70% | 0.14 | 机构困境、资金流、政策 |
| D1 | 55% | 0.16 | + 信用、盈利 |
| D2 | 45% | 0.18 | 全部 |
| D3 | 35% | 0.20 | 全部 + **对手方可主动投放假消息** |

- **生成频率**：平静期每 3–5 个交易日一条，危机期每 1–2 个交易日一条，危机顶点**每日 2–3 条**。**信息过载本身也是难度的一部分。**

### 三种特殊传闻

**① 自我实现型**
- `rumor_bailout_coming`：市场相信会被救 → 融资压力下降 → 真的不用救。
- `rumor_bank_run`：**即使最初是假的，被相信之后也会变成真的。**

**② 预警型（本作最关键的一类）**

`rumor_repo_haircut_jump` 与 `rumor_repo_maturity_shortening` 对**价格几乎无影响**，但会提前告知融资机制即将恶化。只有 D2 及以上玩家能看到这两条。

> 同样的传闻，低难度玩家看到的是"无关紧要的消息"，高难度玩家看到的是"我三天后要被追加保证金了"。**这是难度梯度最纯粹的表达方式——不是给你更少的信息，而是让你有能力读懂同样的信息。**

**③ 直接指向玩家的**

| 传闻 | 效果 |
|---|---|
| `rumor_sec_watching_player` | 只作用于玩家自己的 SRS（+0.05），不改变市场 |
| `rumor_disclosure_breach` | 对应监管阶梯 L2（5% 强制披露），SRS +0.08 |
| `rumor_margin_hike` | 唯一能改变账户规则的传闻（保证金要求 ×1.25） |

## 8. 状态谓词参考

`requires` / `requireAnyOf` 里除了事件 ID，还可以引用状态谓词。当前校验器允许的模式：

| 模式 | 示例 | 含义 |
|---|---|---|
| `credit_spread_above_<bp>` | `credit_spread_above_800` | 信用利差突破阈值 |
| `player_short_concentration_<TICKER>_above_<n>pct` | `player_short_concentration_LEH_above_5pct` | 玩家对某标的的空头占流通股比例 |
| `vix_above_<n>` | `vix_above_75` | VIX 突破阈值 |
| `ted_spread_above_<n>` | `ted_spread_above_3.0` | TED 利差突破阈值 |
| `liquidity_below_<n>` | `liquidity_below_0.2` | 市场流动性状态 |
| `srs_above_<n>` | `srs_above_0.5` | 玩家系统性风险分 |

> 注意：事件卡里 `state` 型触发器用的是**表达式字符串**（如 `"systemicStress > 0.7"`、`"vix > 75"`），而上面的谓词语法用于 `requires` / `requireAnyOf`。两者由引擎的**同一个条件求值器**处理，见 [02 文档](02-系统架构与数据结构.md)。

`player_short_concentration_*` 是本作独有的谓词：**它让玩家可以成为事件的触发者。** 见 `lehman_collapse` 的 `requireAnyOf`。

## 9. 如何新增一张事件卡

```bash
# 1. 在对应的 events-*.json 里按 schema 添加
# 2. 校验数据集
python tools/validate_events.py

# 3. 把时间线表写回本文档（自动替换 BEGIN/END TIMELINE 标记区内容）
python tools/gen_timeline.py --write

# 4. CI 里检查文档与数据是否同步
python tools/gen_timeline.py --check
```

**必须通过的校验**（`tools/validate_events.py`）
- 必备字段齐全（`id/phase/date/title/headline/narrative/window/trigger/tier/impact`）
- `trigger.type` ∈ {`scheduled`, `competing_risk`, `state`}
- `tier` ∈ {`macro`, `policy`, `funding`, `investment_bank`, `commercial_bank`, `insurer`, `gse`, `overseas`}
- ID 全局唯一
- `requires` / `requireAnyOf` / `unlocks` / `exclusiveWith` 引用可解析
- `window` 合法且 `date` 落在其中
- 因果 DAG 无环
- `|indexReturn| ≤ 0.25`
- 分层约束：`gse` / `insurer` 层不得早于投行/银行层的首个系统性事件

**写作要求**
- `narrative` 里必须有一句"这一课是什么"。事件卡不只是触发器，它是教学单元。
- 冲击数值要与新闻强度匹配。不要出现"雷曼破产 + 指数跌 0.5%"。
- 如果是陷阱，加 `isTrap: true` 与 `trapNote`。
- 如果数值是估算的，不要伪装成精确回测——数据集头部已声明所有 `impact` 为设计校准值。
- 融资类事件用 `tier: "funding"`，并优先修改 `repoHaircutDelta` / `rolloverRateDelta` 而不是 `indexReturn`。**机制恶化比价格下跌更有杀伤力。**
