# 05 · 事件系统与危机排序机制

> 本文档回应一个关键设计问题：**能不能让随机变量控制"谁先倒"，而不一定是贝尔斯登？**

---

## 1. 三种做法对比

### 做法 A：随机洗牌（不推荐）

把机构失败顺序随机打乱：这次雷曼先倒、下次高盛先倒、再下次美林先倒。

**问题（四个，每个都致命）**

1. **叙事崩塌。** 新闻说"高盛破产"，但没有任何前因支持它——玩家会觉得这是随机数在耍他。
2. **DAG 全面失效。** 后续事件的前置条件（"至少一家投行倒下"）形同虚设，事件之间的因果链断裂。
3. **教育价值归零。** 历史上贝尔斯登先倒**是有原因的**：杠杆最高（33×）、回购融资依赖最重（~32%）、结构化产品敞口最大、且它是五家中规模最小、最容易失去信心的。把它随机化，等于抹掉了这一课。
4. **玩家无法预判。** 如果顺序是纯随机的，观察指标就没有意义，游戏退化成抽奖。

### 做法 B：固定历史顺序（太保守）

**问题**：玩家背日期就能通关，二周目毫无价值。

### 做法 C：竞争风险模型（★ 推荐）

**顺序不是被随机决定的，而是从机构的脆弱度状态中涌现的。**

随机性依然存在，但它作用于**谁先撑不住**，而不是**凭空指定谁先死**。这样你同时得到了随机性和因果性——而且玩家能通过观察指标来预判，只是预判不会 100% 准确。

## 2. 竞争风险模型

### 2.1 机构脆弱度 F

每个系统重要性机构维护一个脆弱度分数：

```
F_i = w1·norm(leverage_i)
    + w2·norm(repoDependence_i)
    + w3·norm(assetImpairment_i)
    + w4·(1 − confidence_i)
    + w5·norm(counterpartyExposure_i)
    − w6·norm(capitalBuffer_i)
```

| 分量 | 含义 | 初始数据来源 |
|---|---|---|
| `leverage` | 总资产 / 权益 | 10-K 财报，公开 |
| `repoDependence` | 短期回购融资占负债比 | 财报脚注 |
| `assetImpairment` | 结构化产品 / 次级 MBS 敞口受损程度 | 逐季减记公告 |
| `confidence` | 市场信心（0–1），**顺周期变量** | 新闻驱动的状态量 |
| `counterpartyExposure` | 对其他脆弱机构的敞口 | 交易对手网络 |
| `capitalBuffer` | 可吸收损失的能力 | 权益 / 风险加权资产 |

建议权重：`w = [0.22, 0.20, 0.24, 0.16, 0.12, 0.06]`

### 2.2 失败风险率（hazard）

```
hazard_i(t) = baseHazard × exp( κ · (F_i(t) − F̄(t)) / σ_F ) × systemicStress(t)
```

- `baseHazard` = 每个交易日的基础失败概率（约 0.004）
- `κ` = 脆弱度敏感度（建议 1.2）——越高则"最脆弱者先倒"越确定
- `systemicStress(t)` = 系统性压力（由信用利差、VIX、流动性状态合成）

每个交易日，对同层（见 §4）的所有机构计算 hazard，**做一次抽样**决定是否有人倒下、是谁。

**当 `κ` 很大时，结果接近历史顺序；当 `κ` 很小时，结果接近随机洗牌。** 这就是难度与时间线模式的旋钮。

### 2.3 为什么这个方案是对的

| 要求 | 是否满足 |
|---|---|
| 有随机性 | ✅ 每次运行顺序可能不同 |
| 因果自洽 | ✅ 脆弱的人先倒，符合直觉与历史 |
| 玩家可预判 | ✅ 信用利差、股价、评级是公开信号 |
| 玩家能影响 | ✅ 见 §2.4 |
| 教育价值保留 | ✅ 玩家能学到"为什么是它先倒" |
| DAG 不失效 | ✅ 用 `requireAnyOf` + 分层约束 |

## 3. 玩家影响力（你提到"玩家资金过大会引入波动"）

这是整件事最有价值的部分。**玩家的行为可以改变谁先倒。**

```
玩家大量做空某机构
  → 股价下跌
  → confidence 下降（新闻开始报道）
  → assetImpairment 被市场重估
  → F_i 上升
  → hazard_i 上升
  → 该机构更可能先倒下
```

**两个方向都成立：**

| 玩家行为 | 后果 |
|---|---|
| 猛烈做空雷曼 | 雷曼的 F 上升，**可能取代贝尔斯登成为第一个倒下的** |
| 大量买入/护盘某机构 | 该机构 F 下降，历史被推迟甚至改写 |
| 做空整个板块 | 所有 F 上升，`systemicStress` 上升，危机整体提前 |

**所以"不一定是贝尔斯登先倒"这个体验，不该来自随机洗牌，而该来自玩家自己。**

如果玩家把雷曼做空到第一个倒，那不是系统在随机——那是**他亲手造成的**。这个因果链条的满足感远高于随机数。

## 4. 分层排序约束

**不是所有机构都能自由排序。** 必须分层，因为它们的死法机制根本不同。

| 层 | 机构 | 可排序性 | 死法 |
|---|---|---|---|
| **L1 投行层** | BSC, LEH, MER, GS, MS | **完全可排序** | 流动性挤兑 → 被收购 / 破产 / 转型 |
| **L2 商业银行层** | WM, WB, C, IMB, CFC | 部分可排序 | 存款挤兑 → 接管 / 被收购 / 救助 |
| **L3 保险层** | AIG, MBIA, AMBAC | 顺序受限（必须在信用事件之后） | 抵押品追缴螺旋 → 救助 |
| **L4 政府支持层** | FNM, FRE | **顺序几乎固定**（政策决定，非市场决定） | 政府接管 |
| **L5 海外层** | NRK, RBS, HBOS, UBS, Fortis | D3 才启用，独立于美国主线 | 挤兑 / 国有化 |

> 说明：两房被接管是**政策决定**而非市场决定，它的时点由财政部的政治意愿驱动。所以它的排序自由度应该显著低于投行层。这本身就是一堂关于"政府支持企业"的课。

**跨层约束**：L3/L4 的事件不能早于 L1/L2 的首个失败事件。这不是硬编码顺序，而是"传染必须有源头"的物理约束。

---

## 5. 概率分布要求

排序随机化必须保持**主峰 + 重尾**，不能是均匀分布。

在历史参数、无玩家干预、`κ = 1.2` 下，"第一个倒下的投行"概率分布应大致为：

| 机构 | 概率 | 理由 |
|---|---|---|
| 贝尔斯登 BSC | **~62%** | 杠杆最高、规模最小、回购依赖最重 |
| 雷曼 LEH | ~18% | 次高脆弱度。历史模式之外的常见变体 |
| 美林 MER | ~12% | 资产质量最差，但融资结构稍好 |
| 摩根士丹利 MS | ~5% | 需要额外的负面冲击才会触发 |
| 高盛 GS | ~3% | 最难倒。倒它需要玩家或事件的强烈干预 |

**校验规则**：如果 10000 次模拟里"高盛第一个倒"的概率超过 15%，说明 `κ` 太小或参数失衡，历史感会流失。

## 6. 扩展事件卡 Schema

在 [02 文档](02-系统架构与数据结构.md) 的 `EventCard` 基础上增加三个字段，用于支持非确定顺序：

```ts
interface EventCard {
  // ... 原字段

  /** 硬前置：全部满足才可能触发 */
  requires: string[];

  /** 软前置：满足任意一组即可触发。用于"至少一家投行已倒下"这类条件 */
  requireAnyOf: string[][];

  /** 触发方式 */
  trigger:
    | { type: 'scheduled' }                                   // 到窗口内按概率触发
    | { type: 'competing_risk'; institution: string; baseHazard: number }  // 竞争风险
    | { type: 'state'; predicate: string };                    // 状态满足即触发

  /** 对本事件中机构之外的其他机构脆弱度的影响 */
  affectsFragility?: Record<string, number>;

  /** 注入监管规则（如做空禁令），写入 RegulatorState.activeRules */
  imposesRule?: { kind: 'short_ban' | 'margin_hike' | 'disclosure' | 'circuit_breaker'
                       | 'bailout';
                  scope: string[]; durationDays: number };

  /** 互斥事件：雷曼破产 vs 雷曼获救，二者只能发生一个 */
  exclusiveWith?: string[];

  /** 分层约束。funding 层见 docs/07 */
  tier?: 'macro' | 'policy' | 'funding'
       | 'investment_bank' | 'commercial_bank'
       | 'insurer' | 'gse' | 'overseas';
}
```

### 示例：雷曼倒下

```jsonc
{
  "id": "lehman_collapse",
  "tier": "investment_bank",
  "window": ["2008-06-01", "2008-12-31"],
  "requires": ["housing_downturn", "subprime_delinquency_rise", "repo_funding_stress"],
  "requireAnyOf": [
    ["bear_stearns_collapse"],                     // 历史路径
    ["merrill_merger"],                            // 变体：美林先倒
    ["credit_spread_above_800"],                   // 变体：信用事件先到
    ["player_short_concentration_LEH_above_5pct"]  // 变体：玩家做空引发
  ],
  "trigger": { "type": "competing_risk", "institution": "LEH", "baseHazard": 0.06 },
  "affectsFragility": { "AIG": 0.35, "MER": 0.20, "GS": 0.15, "MS": 0.15 },
  "exclusiveWith": ["lehman_rescue_variant"]
}
```

## 7. 三种时间线模式

| 模式 | 日期抖动 | 排序随机 | 事件可被改写 | 适用 |
|---|---|---|---|---|
| `historical` | 无 | 无（严格历史） | 否 | 教学、回放、成就校验 |
| `jittered`（**默认**） | ±10 交易日 | `κ = 1.2` | 部分 | 正常游玩 |
| `parallel` | ±30 交易日 | `κ = 0.5` | 是 | 二周目、挑战模式 |

**关键约束（三种模式都适用）：新闻强度必须与价格冲击绑定。** 随机的是"何时"和"多深"，不是"是否"和"方向"。见 [02 §7.2](02-系统架构与数据结构.md)。

## 8. 校验规则（自动化测试）

事件卡数据集必须通过以下断言，否则引擎拒绝加载：

- [ ] **DAG 无环**：拓扑排序成功
- [ ] **可达性**：每张卡都能在某个 seed 下被触发（跑 1000 次模拟验证）
- [ ] **必达性**：`isSystemicEvent: true` 的卡在 95% 以上的运行中至少在窗口内触发一次
- [ ] **分层约束**：不存在"两房先于任何投行/银行失败"的运行
- [ ] **概率分布**：§5 的分布要求，偏差超过阈值则报警
- [ ] **数值边界**：`impact` 不得让任何指数单日跌幅超过 −25%（超出则 clamp 并报警）
- [ ] **窗口合法**：`window[0] <= window[1]`，且都落在游戏时间轴内
- [ ] **ID 唯一**：`requires` / `requireAnyOf` 引用的 id 全部存在
- [ ] **新闻一致性**：每张卡都有 `headline` 与 `narrative`，非空

## 9. 一个必要的自我约束

**不要把所有事件都做成可随机。** 有些事件是**结构性**的，必须固定：

| 必须固定 | 原因 |
|---|---|
| 房价下跌先于次贷违约 | 物理因果 |
| 次贷违约先于结构化产品亏损 | 会计因果 |
| 货币基金跌破面值先于商业票据市场冻结 | 机制因果 |
| 见底与反弹发生在救助之后 | 政策因果 |

**随机化只作用于"谁、何时、多深"，不作用于"什么导致了什么"。**

守住这条，游戏才既有变化又可信。
