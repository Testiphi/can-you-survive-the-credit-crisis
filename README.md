以 2007—2009 年信贷危机为背景的单人回合制交易模拟游戏。玩家根据当时可见的行情和消息安排交易，管理现金、持仓与到期义务。

**[在线试玩](https://testiphi.github.io/can-you-survive-the-credit-crisis/)** · 无需安装或注册。

当前稳定演示范围是 **D0：五个独立历史章节 × 四种角色**，另可选择完整三年复演。D1—D3 保留为实验模式，其复杂规则仍在整理中。基础数据包含 94 张事件卡、21 家机构参数和 38 类传闻模板；D0 不启用程序化传闻。

## 从哪里开始

推荐选择 **D0 → 散户 → 危机初现**。可以直接进入任一章节，也可以在结算后选择下一章。

1. 查看开场背景、当前行情和“最近期限与资金缺口”。
2. 选择标的及 25%、50% 或 100% 的交易比例，先看下单预览。
3. 买卖或平仓后推进一个交易日，查看实际成交与资金变化；观望最多推进五个交易日。
4. 到章节结束时核对本金目标、履约情况和风控挑战。

每章会重置资金、持仓和角色合同，不继承上一章账户；角色选择保留。各角色的章节达标记录保存在当前浏览器。完整复演的新局从 2007-01-03 开始，到 2009-12-31 结束。

### 五个章节

| 章节 | 日期 | 本金保留目标 | 最大回撤挑战 |
|---|---|---|---|
| 危机初现：留出余地 | 2007-07-02 — 2007-08-31 | 85% | 20% |
| 贝尔斯登：资产与现金 | 2008-02-01 — 2008-03-31 | 80% | 25% |
| 危机高峰：守住本金 | 2008-09-02 — 2008-10-31 | 70% | 30% |
| 政策转折：重新评估方向 | 2009-03-02 — 2009-04-30 | 80% | 25% |
| 修复期：退出紧急状态 | 2009-05-01 — 2009-06-30 | 80% | 25% |

章节达标要求生存至结束、完成到期义务并达到本金目标。最大回撤和避免自动回补是额外挑战。基金的本金指标会加回已返还投资者的资本，避免把赎回当作投资亏损。这些阈值是游戏目标，不是投资建议。

### 四种角色

| 角色 | 初始自有资金 | 主要任务 |
|---|---|---|
| 散户 | 10 万美元 | 控制多空仓位，保留现金 |
| 基金经理 | 1000 万美元 | 管理投资与两笔投资者赎回 |
| 银行资金经理 | 10 亿美元 | 接手证券和借款，安排偿债或展期 |
| 保险公司 | 100 亿美元 | 准备赔款，决定是否提前购买再保险 |

角色范围固定为这四种，后续优先完善共用操作、内容节奏、平衡与复盘。

## D0 的交易与结算

D0 只提供标普 500（SPX）和花旗（C）两个标的，使用价格线与历史时间线。新手可见的历史新闻按日期展示，非交易日事件顺延；开局已知背景立即显示，回顾性正文在本局结束后展示，避免提前透露后续走势。

- **下单预览**：显示预计成交数量、手续费、仓位方向变化和付款现金缺口。按钮会区分减仓、平仓、回补及反向开仓。预览不会消耗随机状态，实际成交仍取决于次日开盘价与约束。
- **仓位限制**：新增交易后的多空绝对持仓总额，散户、基金和保险公司最多为净资产的一倍，银行教学版最多两倍；现金不能透支。减仓与平仓不受新增额度限制，卖空所得不能无限用于加仓。
- **交易成本**：手续费为成交金额的 0.05%；空头按当日市值收取固定年化 0.5% 的持有费，每交易日计提年费的 1/252。
- **空头风险底线**：收盘净资产低于空头市值的 30% 时，按收盘价回补有报价的空头，收取正常手续费。行情缺失时等待恢复报价，跳空仍可能使损失超过本金。
- **时间推进**：买卖与平仓推进一天；观望最多五天，遇到事件、成交、账户风险、角色资金通知或本次观望期间净值下跌 3% 时提前暂停。没有可提交数量时不会推进时间。
- **资金报告**：区分投资价差、手续费、借券费、利息、保费与赔款；还本、赎回和已确认赔款的支付分别处理，避免重复记损益。

D0 不创建 NPC，不生成真假传闻，不执行旧回购模型和监管处罚。银行教学版的借款、展期和抵押追缴由独立合同账本处理。

### 基金经理：赎回义务

开局后第 10、25 个交易日收盘，各兑付初始资金的 10%。日期与金额预先公开，到期前一交易日会提醒并暂停观望；此时提交的平仓单可在到期日开盘执行。

可兑付现金为现金扣除空头现值的两倍，下限为零，为卖空所得及等额自有担保资金留出空间。未按期兑付即结束本局，即使净资产仍为正；未支付金额不会被扣掉。

已兑付金额属于外部资本返还。收益、本金目标与回撤使用“剩余净资产＋累计返还资本”，这是教学保本指标，不是基金份额净值或时间加权收益率。

### 银行资金经理：借款与展期

开局借入与自有资本等额的资金，继承约一倍资本的标普持仓、半倍资本的花旗持仓，其余为现金。两笔借款各占初始资本的一半，于第 15、30 个交易日收盘到期，初始年化利率 5%，逐日按未还本金计息。

“提前偿债”在下一交易日收盘执行，按当前到期顺序先清应计利息，再还本金，允许部分偿还。到期则要求足额支付。还本同时减少现金和负债，不产生投资损失。

到期前五个交易日至到期日可申请展期，每笔最多一次，新期限不超过本局结束日。下表中的系统压力 S 在 0—1 之间，均为教学模型参数。

| 方案 | 从执行日起延长 | 新年化利率 | 一次性手续费 | 条件 |
|---|---|---|---|---|
| 抵押展期 | 10 个交易日 | 6%＋4%×S | 续借本金的 0.2% | 证券多头提供共享抵押额度，折扣为 20%＋50%×S |
| 无抵押展期 | 20 个交易日 | 10%＋4%×S | 续借本金的 0.5% | 净资产至少为本笔本金的一半 |

报价按当前状态估计。次日收盘先按旧利率计息，再重新审核；成功后支付应计利息、费用与需补还本金，新利率次日起生效。拒绝时不扣展期费、不改变原合同。

抵押池不会重复质押。资产下跌、卖出或折扣上升产生缺口时，先用可用现金补还本金；现金不足则给一个交易日处理，逾期仍不足即违约。卖空担保资金不能用于还债。

### 保险公司：赔款与再保险

两笔教学赔案在第 15、30 个交易日确认，次日支付。每笔金额为初始资本的 `3%＋17%×确认日系统压力`；金额范围和日期公开，实际金额在确认前不展示。现有保单从开局后第一个交易日至最后赔付日（含当日），每交易日带来初始资本 0.04% 的收入，此后停止。

第 5 个交易日收盘前可购买一次再保险，保费为初始资本的 `5%＋4%×成交日系统压力`。每案先自留初始资本的 5%，超过部分由再保险承担 50%。购买后不退费，不能在赔款揭晓后补买。

确认赔案时记入赔款负债和再保险应收，确认净损失；次日先收再保险款，再支付赔款，不重复扣减净资产。现金不足即结束本局，未付金额仍保留为负债。教学版不模拟再保险方违约或完整保险会计准则。

**合同范围**：完整三年模式也只包含上述两笔教学赎回、两笔借款或两笔赔案，不会自动生成多年连续业务。

## 存档与版本兼容

D0 每次操作后自动保存。刷新后可继续上次游戏；开始新 D0 游戏会覆盖当前存档。支持导出 JSON 和导入恢复，导入成功前会先完成回放与状态校验，错误文件不会覆盖原存档。

存档包含配置、操作日志、待执行指令及数据和状态校验值。章节进度单独保存在浏览器中，不属于导出文件中的账号成绩。该机制用于续玩与复现问题，不提供防作弊铁人模式；D1—D3 暂不支持续玩。

| 标记 | 当前含义 |
|---|---|
| `demoVersion: 1` | D0 新局的开场背景、历史前置事实与事件修订 |
| `marketRevision: 1` | 新局使用早期 OHLC 修订，并在起始日有数据时显示完整日线 |
| 未携带上述标记 | 按对应旧版规则或行情恢复，保持回放结果 |

数据修订沿用原事件 ID 与依赖结构。新 demo 根据[高盛官方公告](https://www.goldmansachs.com/pressroom/press-releases/2009/tarp-repurchase)，把 TARP 回购日期从原数据的 2009-06-02 修订为 2009-06-17。原数据保留用于旧存档，修订逻辑见 [demo.ts](packages/core/src/demo.ts)。

## 行情数据与 K 线修复

历史行情主数据位于 [market.json](data/processed/market.json)，来自新浪美股日线；SPX、GS、MS、JPM、C、AIG 有历史序列。LEH、BSC、MER、WM、FNM、FRE 等使用合成路径，不能当作精确历史价格。

GS、MS、AIG、C、JPM 在 2007-01-03 至 2007-03-16 原有各 51 天零成交量、开高低收相等的回填记录，导致蜡烛显示为横杠。2026-10-07 修复时，Yahoo Finance chart API 可用，补齐了五个标的共 **255 根日线**。

补丁保存在 [early-ohlc.json](data/processed/early-ohlc.json)，不覆盖旧主数据。以 2007-03-19 至 23 的五日重叠 OHLC 核对价格口径：GS/JPM/AIG 缩放为 1，C 为 0.1，MS 约为 0.8360268，最大相对偏差小于 0.01%。成交量按既有口径调整（AIG ×20、C ×10、其余 ×1），保留提供商统计差异，来源 URL 与缩放参数均入库。

新开局使用修订行情。旧存档为保持复现仍使用原行情；标准图表把缺少日内数据的估算段显示为灰色虚线，隐藏该段蜡烛及模拟成交量。管道也已修正开头缺口倒推收益的方向，并保留 `filled` 标记。

D0 有历史日线时直接采用数据集 OHLC，不重复叠加事件涨跌；缺失整日报价时暂用前日估值并暂停该标的成交。D1—D3 仍保留事件扰动和合成机制，不能声称所有难度都精确复现历史。宏观与压力指标含设计校准值。

构建使用已入库 JSON，不需要在线下载行情。重建数据才需要访问外部提供商；网络可用性应以实际运行结果为准。

## 本地运行

环境：Node.js 22 的近期补丁版本（与 CI 一致，需支持直接执行 `.ts`）、pnpm 11.7.0；Python 检查使用 3.12，脚本依赖标准库。

```bash
pnpm install --frozen-lockfile
pnpm --filter @cyscc/web dev

# 生产构建与预览
pnpm --filter @cyscc/web build
pnpm --filter @cyscc/web preview
```

构建产物位于 `apps/web/dist`。前端使用 React Hooks、Vite 和 lightweight-charts；图表、React 与主程序分块。核心引擎位于 `packages/core`，没有 DOM 或第三方运行时依赖，可直接在 Node 中运行。

### 检查与模拟

```bash
# 引擎与回归检查，无需安装前端依赖
node --test "packages/core/test/*.test.ts"
python -m unittest discover -s tools -p "test_*.py"

# 事件结构与目录同步，只读检查
python tools/validate_events.py

# CI 使用的策略冒烟与价格量级检查
node packages/core/test/balance-report.ts 4 1

# 手动模拟：[seed] [难度] [策略]
node packages/core/test/manual-sim.ts 42 1 cash
# 支持 cash | long | short | short-then-long

# 候选时期覆盖检查
node tools/period-readiness.ts
```

最近一次实现验收基线为 [33555a5](https://github.com/Testiphi/can-you-survive-the-credit-crisis/commit/33555a5)：139 项 Node 测试、1 项 Python 管道回归、事件校验、价格检查、策略冒烟和前端构建通过。覆盖 20 个章节角色组合的完整运行、保守达标路线、存档回放、赔付与债务账目以及早期 OHLC 修复。本地浏览器检查了选章、下一章、导入导出和 P3 行情，线上 CI 与部署通过。

测试通过不代表策略已充分平衡，也不等于精确金融回测。性能和策略结果会随代码、参数与运行环境变化，README 不把旧版耗时或收益分布当作当前保证。

### 数据维护

```bash
# 更新事件数据后，重新生成目录
python tools/gen_timeline.py --write

# 以下命令会访问网络，--write 会更新补丁
python tools/repair_early_ohlc.py --write
python data/pipeline/build_market.py

```

主行情重建和早期补丁构建是不同操作。补丁仅允许替换指定区间的回填数据；日期覆盖、OHLC 或重叠口径校验失败时停止。更新基础数据会影响存档指纹，需要同时检查版本兼容，不能仅重新下载后直接发布。

## GitHub Pages 部署

推送 `main` 会触发 [CI](.github/workflows/ci.yml) 和 [Pages 部署](.github/workflows/deploy-pages.yml)。部署前执行引擎测试、事件校验、Python 管道回归、价格量级与策略冒烟检查，再构建和发布。

工作流尝试自动启用 Pages；权限不足时需在仓库 Settings → Pages 中选择 GitHub Actions。项目页面需要仓库路径前缀，工作流通过 `VITE_BASE_PATH` 配置，本地默认 `/`。

PowerShell 下可这样复现部署路径：

```powershell
$env:VITE_BASE_PATH = '/can-you-survive-the-credit-crisis/'
pnpm --filter @cyscc/web build
Remove-Item Env:VITE_BASE_PATH
```

## 当前边界与后续方向

- D0 使用历史时间线，关闭 NPC、程序化传闻和旧监管机制；D1—D3 为实验模式，尚未完成同等程度的玩法整理。
- 教学合同、报价和压力函数经过简化；期权、期货、自由场外合约等原规划不属于当前完整 demo。
- 浏览器存档与进度不提供账号同步、排行榜或防篡改保证。
- 行情仍包含历史、修订、回填与合成来源；首日背景和事件目录并不等同于全部史实已经逐条核验。

后续优先改进章节节奏、策略平衡和失败复盘，保留现有四角色。时期扩展沿用原事件 ID、前置依赖与互斥结构。

2008 年 2—3 月和 2009 年 5—6 月已经开放。下一次跨年目标仍是 **2010 年 4—6 月**；当前尚无对应行情与事件数据，交易日历、宏观压力曲线和存档日期边界也需扩展。先补数据与版本兼容，再做章节验收，不能只延长结束日期。

本作是历史背景下的教学模拟，不构成投资建议。代码按 [MIT License](LICENSE) 发布，第三方行情与资料不因代码许可证而自动获得相同授权。
