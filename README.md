## 一句话定位

你在 2007 年 1 月手握一笔资金，面对一条**终将崩盘、但崩盘时间与幅度不确定**的市场。
你只能看到今天及以前的信息——明天是未知的。

你的目标不是"猜对方向"，而是**在融资断裂、流动性消失、对手方接连倒下的环境里活下来，并且赚钱**。

---

## 六条核心设计立场

1. **难度来自约束，不来自信息。** 数据给得越多，游戏越简单——这是本作最容易走反的一条路。
2. **2008 年的核心是融资断裂，不是股价下跌。** 融资能力必须是一等公民机制，而不是一个数字。
3. **NPC 有各自的目标，不针对玩家。** 但玩家自己的规模会改变市场——大到一定程度，会引来监管。
4. **随机的是"何时"和"多深"，不是"是否"和"方向"。** 新闻强度必须与价格冲击绑定。
5. **不可逆是一起紧张感的来源。** 默认铁人模式：单一存档、不能回退。
6. **每一个数据/工具都必须改变玩家的一个决策**，否则不做。

## 界面

游戏有两套**完全不同的界面**，按难度切换——D0 不是「主界面少显示几项」，
而是换一套交互模型。

### D0 · 新手模式（默认）

角色第一轮扩展：

- 散户：用自有资金交易，按所选时期的本金与回撤目标结算。
- 基金经理（教学版）：在散户交易规则上增加两笔已公开的投资者赎回。开局后第 10、25 个交易日收盘，各支付初始资金的 10%；到期前一交易日自动暂停观望并提醒，此时提交的平仓单可在到期日开盘成交。
- 可兑付现金为账户现金扣除空头现值的两倍，给卖空所得及等额自有担保资金留出空间。不能通过卖空临时制造可兑付现金。
- 未按期兑付即结束本局，原因与净资产破产区分；不会偷偷扣掉未支付金额或自动替玩家卖仓。完整三年模式也只安排开局后的这两笔教学兑付。
- 兑付是外部资本返还：日报单列该项，投资损益和最大回撤基于“剩余净资产＋累计已返还资本”，本金目标也使用这个合计。这是本游戏的保本指标，不是基金份额净值或时间加权收益率。
- 原有散户存档可继续恢复；基金存档也使用相同的操作回放和校验机制。


可选时期：

| 章节 | 日期 | 本金保留目标 | 最大回撤挑战 |
|---|---|---|---|
| 危机初现：留出余地 | 2007-07-02 — 2007-08-31 | 85% | 20% |
| 危机高峰：守住本金 | 2008-09-02 — 2008-10-31 | 70% | 30% |
| 政策转折：重新评估方向 | 2009-03-02 — 2009-04-30 | 80% | 25% |

这些阈值是公开的游戏目标。完整三年模式仍可选；时期通过日期识别，不改变已有散户存档格式。


默认推荐短章节“危机高峰：守住本金”（2008-09-02 至 2008-10-31，共 43 个决策推进日）；可切换完整 2007—2009 复演。章节目标是保留至少 70% 初始净资产，附加挑战为最大回撤不超过 30%、不触发自动回补，空仓可以达标。每日报告拆分价差损益、手续费、做空持有费；结束时展示实际结果与最大单日损失。历史新闻的回顾性正文在局内隐藏，结束后再展示，避免提前透露后续走势。


D0 每次操作后自动保存到当前浏览器；刷新后在开始页选择“继续上次 D0 游戏”。开始新 D0 游戏会覆盖该存档。存档包含配置、完整操作日志、待成交订单及数据/状态校验值，恢复时重放验证；不兼容或损坏时保留原记录并提示原因。浏览器禁用存储或容量不足时会显示保存失败。此功能不等于防篡改铁人模式，D1 及以上暂不提供续玩。


| | |
|---|---|
| 标的 | **2 个**：标普 500（美国股市大盘）、花旗集团（美国最大的银行之一） |
| 图表 | **一条价格线** + 起始基准线。没有蜡烛、没有成交量、没有均线 |
| 操作 | **买入 / 做空 / 观望 / 平仓**，可选 25% / 50% / 100% 交易比例 |
| 节奏 | 买卖和平仓推进 1 个交易日；观望最多推进 5 日，遇到事件、成交、追保或期间净值下跌 3% 时提前暂停 |
| 账户 | **模拟盘**：可用现金 / 持仓市值 / 总资产 / 浮动盈亏 / 最近成交 |
| 新闻 | **一条都没有削减** |

设计要点：

- 蜡烛图 + 成交量 + 均线对完全没接触过交易的人是**纯噪声**——看不出该看什么。
  一条线配一条起始基准，回答了新手唯一关心的问题：现在比我第一次看到它时，高了还是低了
- 「观望」是一个**正经的选择**，不是死按钮。危机里空仓也是一种仓位
- 「平仓」卖出多头、买回空头；部分成交会保留剩余持仓。
- D0 在次日开盘按实际成交价和手续费限制新增仓位，多空持仓绝对金额合计不得超过账户权益。重复订单共享额度，卖空所得不能用于反复加仓；减仓和平仓不受新增额度限制。
- 上述额度约束只作用于新交易；行情变化仍可能令持仓比例升高，做空仍存在损失超过本金的风险。
- D0 支持散户（默认本金 10 万美元）与基金经理教学版（默认本金 1000 万美元）；不创建 NPC，不生成真假传闻，不执行回购融资、事件禁空和监管惩罚。历史事件及市场影响仍保留，监管新闻附有教学模式说明。
- 做空费用固定为年化 0.5%，按当日空头市值逐交易日计提（1/252），不受事件加价或随机借券召回影响。
- D0 收盘净资产低于空头市值的 30% 时，按收盘价自动回补全部空头并收取正常手续费；没有额外惩罚滑点，不等待补资。成交记录和系统新闻解释原因，多头不因这条规则被卖出。
- D0 固定使用历史时间线：按事件日期播放新闻，非交易日顺延到下一交易日，不受竞争风险或前置条件模型延迟；平行分支不启用。
- D0 有历史日线的标的直接采用数据集 OHLC，不叠加事件涨跌，也不覆盖标普开盘价。中途开始只用起始日及以前的行情估值；没有前序数据时明确标为合成估算。
- 缺失整日行情时沿用上一日估值并暂停该标的成交和自动回补；恢复行情后重新检查风险。没有历史序列的标的仍属合成估算。
- 行情面板区分历史、简化/回填、沿用和合成数据。目前花旗 756 天中有 51 天是开高低收相同的简化日线，不应将这些日子的开盘字段当作真实历史开盘价；该轮没有重新下载或伪造行情。
- 新手最容易卡住的地方是「该什么时候前进」。答案是：你不需要想这件事

### D1+ · 标准模式

| 区域 | 内容 |
|---|---|
| 顶栏 | 日期、权益、收益率、现金、最大回撤、标普/VIX，以及时间控制按钮 |
| 左栏 | 标的切换 · K 线（可开关 MA20/MA60）· **行情数据面板** · 净值曲线 · 下单面板 |
| 中栏 | **情境提示** · 保证金/爆仓横幅 · 新闻流（历史事件与程序化传闻分开标注） |
| 右栏 | 持仓 · 市场指标 · 系统性足迹 · 机构脆弱度 · 已触发事件 |

**行情数据面板**给出了 K 线本身看不出的信息：现价与当日涨跌、当日开高低与振幅、
区间最高/最低（含日期）、距最高点与距最低点、MA20/MA60、年化波动率（60 日与全期）、
成交量与 20 日均量比值。

**引导**是分层做的：

- **全量悬浮提示** —— 每个按钮、每个指标名都有。鼠标移上去（或键盘 Tab 聚焦）就弹出多行说明
- **术语词典** —— 每个指标都讲三层：它是什么 / 什么水平算危险 / 它和你该做的决定什么关系
- **情境提示** —— 按难度与当前状态生成 0–3 条。低难度会额外教你怎么读指标；
  高杠杆、追保、压力飙升这类危险提示任何难度都会出现

> 提示渲染在 document 层级而不是用纯 CSS 的 `::after`——因为主内容区有 `overflow-y: auto`，
> 纯 CSS 提示会被容器裁掉，靠边的按钮根本看不到说明。

### 同一天可能有多个事件

一个回合触发多个事件**是正确行为，不是 bug**：

> 2008-09-15，雷曼兄弟申请破产保护的同一天，美林被美国银行收购。
> 真实历史就是这样——最糟的那几天，坏消息是成批到来的。

实测随机模式下约 13% 的事件回合会同时触发 2 个以上，最多 4 个。
这没有被「修」掉：把它压成一天一条，等于抹掉危机最本质的体感——
**你还没来得及消化上一条，下一条已经来了。**

（`packages/core/test/timeline.test.ts` 里有一条测试专门固化这个行为，
防止以后有人把它当成缺陷改掉。）

## 技术栈（拟定）

- **语言**：TypeScript（**核心引擎零依赖、零构建**，靠 Node 22+ 原生类型擦除直接运行）
- **构建/UI**：Vite + React
- **K 线图表**：TradingView `lightweight-charts`（canvas，性能与观感最佳）
- **状态管理**：Zustand
- **引擎**：独立的 `packages/core`，**零 DOM 依赖**，可脱离 UI 在 Node 里批量跑
- **数据预处理**：Python (pandas) → 静态 JSON
- **后端**：v1 不需要。纯前端离线可跑，构建产物是静态文件

### 引擎为什么零依赖

因为它是这个项目里最需要被反复批量验证的部分。零依赖意味着：

```bash
node --test "packages/core/test/*.test.ts"      # 直接跑测试，无需安装任何东西
node packages/core/test/manual-sim.ts 42 1      # 直接跑一局完整模拟
node packages/core/test/balance-report.ts 20 1  # 跑 100 局策略机器人
```

不需要 `npm install`，不需要编译步骤，引擎与 UI 完全解耦。

### 覆盖范围决定了架构

```
真实历史路径：标普 500 · 高盛 · 摩根士丹利 · 摩根大通 · 花旗 · AIG
合成路径：    雷曼 · 贝尔斯登 · 美林 · 华盛顿互惠 · 房利美 · 房地美
```

这个划分**恰好落在设计上合理的位置**：

> 能取到真实历史的，是**活下来的**机构；取不到的，恰恰是**死掉的那些**。
> 而失败机构的终局本来就应该是**事件驱动**的——雷曼归零是 `lehman_collapse`
> 这张卡造成的，不是一条预设的价格曲线。

所以管道**不给退市股伪造历史路径**，而是明确标注在 `synthetic` 字段里。

### 管道要处理的三个数据陷阱

1. **缺口**：新浪的个股历史有真实空洞。高盛的 `2007-01-03 → 2007-03-16` 整段缺失（50 个交易日），
   而标普同期完整。管道按 `beta × 标普收益` 回填，并标记 `filled: true`。

2. **拆股未复权**：AIG 在 `2009-07-01` 的原始序列是 `1.16 → 18.08`（+1458%），
   那是它的 1:20 反向拆股。不处理的话，持有 AIG 穿过拆股日会**凭空获得 20 倍收益**。
   管道用一张**显式的公司行为表**（比启发式检测更可审计）复权。

3. **代码撞车**：新浪按代码匹配，`WM` 返回的是 Waste Management、`WB` 是微博、
   `MER` 是别的基金。所以用**白名单**，不凭代码猜。

### 时间线模式：解决真实性与重玩性的矛盾

真实价格路径是**确定的**——历史只有一条。而事件卡要在浮动的时间点触发，
否则每局都一样、背日期就够了。这两件事天然冲突：
错开太多，玩家就会看到「雷曼破产」的新闻，而价格早在两个月前就跌完了。

解法是把「事件最早/最晚可能发生在哪」与「它历史上发生在何时」**分开**：

- `window`（原字段）= 因果链的合法区间，仍然是**硬边界**
- `date`（原字段）= 史实锚点
- **抖动幅度由时间线模式决定**，即以史实日期为中心的 ±N 个交易日

| 模式 | 抖动 | 实测平均偏移 | 最大 | 落在 ±10 内 |
|---|---|---|---|---|
| **历史回放** | 0 | **0.19** 交易日 | 2 | **100%** |
| **小幅抖动**（默认） | ±10 | 4.95 | 20 | 96.3% |
| **平行时间线** | ±30 | 7.42 | 30 | 73.1% |

历史回放模式下事件**不走概率投掷，也不看状态谓词**——直接按史实记录触发。
这正是它该有的语义：`state` 型卡片（如「对手方风险全面浮现」）的判据由宏观模型
推导，而宏观模型只是对历史的近似（实测它的 `tedSpread > 2.6` 在史实日当天并不满足，
会让做空禁令推迟 9 个交易日）。回放模式下应当以史实为准。

### 实现时踩到的两个坑

**① 窗口收窄会拖死因果链。** 引擎原本对「错过窗口」的补救只开放给
`reversible: false` 或系统性事件。窗口宽达数月时这不成问题；收窄到 ±10 交易日后，
一张普通的 `reversible: true` 卡片错过窗口就**永久失效**，而它若有下游依赖者，
整条叙事线从这一环崩塌——实测 **seed 1 只触发了 3/94 张卡**，贝尔斯登活到了 2009 年底。

修法是结构性的：**凡是有下游依赖者的事件，一律允许迟到触发**。因果链上的必经之路
不能被静默丢弃。

**② 数据集里存在因果倒置。** 校验发现 4 处「前置条件的史实日期晚于依赖它的卡片」，
例如 `new_century_collapse`（2007-04-02）依赖 `subprime_delinquency_rise`（2007-06-01）——
晚了两个月。窗口宽时看不出来，收窄后就是致命伤。

已全部修正，并把这条检查加进 `tools/validate_events.py`（`check_causal_dates`），
以后新增卡片时会自动拦截。

### 真实数据对事件冲击的处理

真实路径本身就包含历史事件的影响，所以事件卡的 `equityReturn` 不能全额叠加
（那是双重计入）。当前做法是按 `REAL_PATH_SHOCK_SCALE = 0.25` 衰减后**当日施加，
不做永久位移**——永久位移会把历史整体拉偏（实测标普期末会低 7%，1032 vs 1115）。

### 平衡状态（D1 · 30 局／策略）

| 策略 | 中位数 | 最差 | 最好 | 爆仓率 |
|---|---|---|---|---|
| cash | 0.0% | 0.0% | 0.0% | 0.0% |
| long | -17.0% | -17.0% | -17.0% | 0.0% |
| short | 49.2% | **-45.1%** | 49.9% | 0.0% |
| short-then-long | **129.3%** | -4.4% | 130.4% | 0.0% |
| random | -100.0% | -114.9% | 1418.0% | 60.0% |

排序符合设计意图：**正确判断（先空后多）＞ 全程做空 ＞ 空仓 ＞ 一直做多 ＞ 乱操作**。

做空不是稳赢：中位 +49.2%，最差 **-45.1%**——空头最怕的正是 2009 年 3 月之后
那波把所有人打爆的反弹。**做空是有限收益、无限风险的交易。**

### 借券费率模型

`基础费率 × 利用率倍数 × 压力倍数`，其中利用率是二次的——真实证券借贷市场
就是这个形态：利用率从 50% 涨到 80%，费率不是涨 60%，而是涨好几倍。

| 情形 | 年化费率 |
|---|---|
| 标普 500（走期货 / ETF，没有借券环节） | 1–3% |
| 流动性好的大票（高盛、摩根大通） | 个位数 |
| 拥挤的做空（吃掉券源一大半） | 数十个百分点 |

两处关键修正（曾经都是 bug）：

1. **指数不计入利用率**。指数没有流通股，早前 `capacityShares = 0` 让利用率落到
   1（满负荷），utilMult 吃满 4 倍——做空标普 500 平静期就要付 23%/年、
   危机期顶到 150% 上限。实测在 2007-10-09 的历史最高点做空并持有到期末，
   指数跌了 28.7%，账户反而**净亏 5.96 万**（借券费 8.4 万 = 毛收益的 3.3 倍）。
2. **压力倍数从 `1 + 120·stress` 降到 `1 + 20·stress`**。旧系数让高盛这种从不难借的
   大票在 2008 年也要付 33%/年。区分「难借」与「好借」的正确维度是**利用率**
   （标的特有），不是全局压力。

> **副作用要说清楚**：修掉这两处之后做空变容易了（中位 31.5% → 49.2%）。
> 这是必然的——旧有的平衡有相当一部分建立在**虚假的摩擦**上。
> 若要把做空压回去，正确的杠杆是召回/逼空风险这一类**真实**摩擦，而不是抬高费率。

### 价格模型检查

价格模型曾经有一组互相叠加的错误，导致金融股在 2007 年年中就全部穿零（高盛 $0.01），
而**所有单元测试依然是绿的**——因为测试断言的是机制，不是量级。现在有了专门的量级检查：

```bash
node packages/core/test/price-check.ts 12 1
```

它验证三件事，任何一条不满足都退出码非零：

| 检查 | 要求 |
|---|---|
| 标普贴合历史锚点 | 每个 seed 都要满足（它由锚点驱动，离散度低） |
| 该死的必须死 | 雷曼、贝尔斯登在每个 seed 都必须归零，且保持归零 |
| 幸存者不能被打死 | 用**中位数**判断——个股特质波动大，单 seed 断言没有意义 |

### 这个工具抓到过什么

`price-check` 上线后立刻抓出一个**静默截断**的 bug：`generateBar` 里的

```ts
clamp(betaPart + idio + jump + extraReturn, -0.35, 0.35)
```

本意是防止随机噪声数值爆炸，却把**事件卡刻意设定的大冲击**一起削平了。
`lehman_collapse` 的 −94%、`bear_stearns_collapse` 的 −90%、花旗国有化恐慌的
−55%，全部被压成 −35%。它们看起来"正确"只是因为死亡衰减逻辑掩盖了结果。

修正后把限幅拆成两层：**随机成分 ±35%，叠加事件冲击后 ±97%**。
花旗的期末价格随即从 $15.3 落到 **$3.48**（实际 $3.34）。

> **教训**：单元测试证明不了「数值是对的」——它只能证明「机制是按设计跑的」。
> 金融模拟必须有一层独立的、面向量级的检查。
